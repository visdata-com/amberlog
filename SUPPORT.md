# Getting Help / 获取帮助

[中文](#中文)

## Where to ask

| What you want to do | Channel |
|---|---|
| Ask about installation, configuration or usage | The Q&A category of [Discussions](https://github.com/visdata-com/amberlog/discussions) |
| Report a bug | [Issues](https://github.com/visdata-com/amberlog/issues/new/choose), choose "Bug report" |
| Propose a new feature or a change to existing behavior | [Issues](https://github.com/visdata-com/amberlog/issues/new/choose), choose "Feature request" |
| Report a security vulnerability | Private vulnerability reporting. **Do not post it publicly.** See [SECURITY.md](SECURITY.md) |

Chinese and English are both welcome.

Before asking, please search Discussions and Issues. Someone may have asked the same question.

## When to expect a reply

Maintainers on duty answer questions about Amberlog on a best-effort basis. Our goal is a first reply within 5 working days. This is a goal, not a service-level commitment.

Security reports have their own time limits; see [SECURITY.md](SECURITY.md).

## What to include

- The full output of `amberlog --version`.
- The type of object storage, for example AWS S3, MinIO or Ceph RGW.
- The configuration and requests involved. **Remove access tokens, keys, certificate private keys and internal addresses first.**
- The relevant server log lines (JSON lines on stderr).

Everything in Discussions and Issues is public and searchable.

## 中文

### 去哪里问

| 你要做的事 | 渠道 |
|---|---|
| 问安装、配置、使用中的问题 | [Discussions](https://github.com/visdata-com/amberlog/discussions) 的问答区 |
| 报告缺陷 | [Issues](https://github.com/visdata-com/amberlog/issues/new/choose)，选「缺陷报告」 |
| 提议新功能或改变现有行为 | [Issues](https://github.com/visdata-com/amberlog/issues/new/choose)，选「功能建议」 |
| 报告安全漏洞 | 私密漏洞报告，**不要公开发帖**。见 [SECURITY.md](SECURITY.md) |

中文、英文都可以。

提问之前，请先搜索 Discussions 和 Issues。别人可能已经问过同样的问题。

### 多久能得到回复

Amberlog 由维护者值守，回复是尽力而为。我们的目标是 5 个工作日内首次回复。这是目标，不是服务水平承诺。

安全漏洞报告的时限另有规定，见 [SECURITY.md](SECURITY.md)。

### 提问时请附上

- `amberlog --version` 的完整输出。
- 对象存储的类型，例如 AWS S3、MinIO、Ceph RGW。
- 用到的配置和请求。**先删掉访问令牌、密钥、证书私钥和内部地址。**
- 相关的服务端日志（stderr 上的 JSON 行）。

Discussions 和 Issues 里的内容都是公开的，可以被搜索。
